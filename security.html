Security & incident response

Last updated: November 17, 2026

Report a vulnerability

Email relayping.support@gmail.com with the subject “Security”. Please do not report vulnerabilities in public GitHub issues. We acknowledge reports within two business days and keep you updated until the issue is resolved.

How RelayPing is built

  • RelayPing runs on Atlassian Forge. Code runs and data is stored on Atlassian's infrastructure; we operate no servers of our own.
  • The only secret we store is each rule's Google Chat webhook URL, kept in Forge's encrypted secret storage. It is never logged and is never shown again after it is saved.
  • Issue content is read only to build a notification and is sent only to chat.googleapis.com. We do not store issue content.
  • Source code access is protected with multi-factor authentication, and the development machine uses full-disk encryption.

Incident response plan

A security incident is any event that may expose customer data or let someone misuse the app, for example a leaked webhook URL, a vulnerability in our code or a dependency, or unauthorized access to our developer accounts.

  1. Detect & record. Incidents may come from a report, an Atlassian security notice, a dependency alert, or app logs. We open a private record with the time, source and what is known.
  2. Assess severity. We rate the issue (critical, high, medium, low) using CVSS and decide whether customer data is affected.
  3. Contain. Depending on the issue we deploy a fix or roll back, disable the affected feature, revoke and rotate credentials, and lock affected accounts.
  4. Notify. For a security incident we open a P1 ticket in Atlassian's Developer and Marketplace Support portal within 24 hours and send Atlassian updates at least every 6 hours until it is contained, following Atlassian's incident management guidelines. Vulnerabilities are fixed within the timelines of the Security Bug Fix Policy. If customer data is affected, we notify affected customers without undue delay, and no later than 72 hours after confirming it, with what happened, what data was involved and what they should do (for example, delete and recreate a Google Chat webhook).
  5. Fix & verify. We release a fix, confirm it works, and check that no other installations are affected.
  6. Review. We write down the cause and the steps that prevent it from happening again.

What you can do

If you think a webhook URL has leaked, delete the webhook in Google Chat, create a new one, and update the rule in Jira under Apps → RelayPing – Google Chat. The old URL stops working right away.

RelayPing is an independent app and is not affiliated with Google or Atlassian.
